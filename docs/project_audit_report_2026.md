## 🔴 CRITICAL Issues

### C1. Tailwind CSS v4 Config Mismatch — All Custom Styles Broken
**Location:** `frontend/tailwind.config.js`, `frontend/package.json`  
**Problem:** Project installs Tailwind CSS v4 (`tailwindcss@^4.2.2`) but uses v3-style JS configuration (`tailwind.config.js`). In Tailwind v4, configuration is CSS-based, not JS-based. The `tailwind.config.js` file is **silently ignored**.  
**Impact:** All custom colors (`primary`, `on-surface`, `secondary`, etc.), custom fonts, custom border-radii, and theme extensions defined in `tailwind.config.js` **are not being applied**. Every `text-primary`, `bg-secondary-container`, `text-on-surface-variant`, etc. class used across all pages resolves to nothing.  
**Fix:** Either downgrade to Tailwind v3, or migrate config to CSS-based format using `@theme` directive in the main CSS file.

---

### C2. Race Condition in User ID Generation
**Location:** `backend/main.py` (signup endpoint)  
**Problem:** `user_id` is generated by counting existing users (`db.query(models.User).count() + 1`). Two concurrent signups can produce the same ID, causing an `IntegrityError`.  
**Impact:** Under concurrent load, signup will crash for the second user.  
**Fix:** Use `uuid4()` (already imported but unused) or database auto-increment for user IDs.

---

### C3. Feature Extraction Divergence — Training vs Inference
**Location:** `data-preparation/03_extract_joint_features.py`, `training_models/clinical_score_prediction_model.py`, `training_models/evaluate_models.py`, `backend/joint_features.py`, `backend/ml_wrapper.py`  
**Problem:** At least 3 different feature extraction pipelines exist:
1. `03_extract_joint_features.py`: 2D aspect-ratio-corrected features (10/8/9/6/8 features per exercise)
2. `clinical_score_prediction_model.py`: Raw joint positions with mid-shoulder normalization, different feature set
3. `evaluate_models.py`: Yet another pipeline — drops face columns, uses raw coordinates

Meanwhile, the backend uses `joint_features.py` which matches path #1 but **models trained with path #2 may not be compatible**.  
**Impact:** Model performance degradation if training and inference use different feature representations. This is the root cause of documented low Spearman ρ values (0.11–0.32).  
**Fix:** Unify feature extraction into a single shared module used by both training and inference.

---

### C4. Missing Model Artifacts in Repository
**Location:** `backend/models/` (empty directory), `backend/data/` (does not exist)  
**Problem:** The `backend/models/` directory is empty. Pre-trained `.keras` models and `.joblib` scalers are not present in the repository. The `backend/data/` directory for SQLite database also doesn't exist.  
**Impact:** Backend cannot start without model files. Docker deployment will fail immediately.  
**Fix:** Either commit model artifacts (if small enough), provide download scripts, or document the model generation pipeline clearly.

## 🟠 HIGH Issues

### H1. Pydantic v2 Deprecation — `orm_mode`
**Location:** `backend/main.py` (Pydantic models)  
**Problem:** Uses `orm_mode = True` in Pydantic model `Config` classes. With `pydantic==2.5.3`, this is deprecated in favor of `from_attributes = True` inside `model_config = ConfigDict(...)`.  
**Impact:** Currently works via compatibility shim but will break in a future Pydantic version.  
**Fix:** Migrate to Pydantic v2 `model_config = ConfigDict(from_attributes=True)`.

---

### H2. Fold Imbalance in Cross-Validation
**Location:** `training_models/clinical_score_prediction_model.py`  
**Problem:** Documented in `docs/fix_fold_imbalance_plan.md` — some folds have very low validation standard deviation, making Spearman/CCC metrics unreliable.  
**Impact:** OOF (Out-of-Fold) evaluation metrics may be misleading. Some folds contribute noise rather than signal.  
**Fix:** Implement `StratifiedGroupKFold` with quantile-based binning (≥5 bins) as recommended in `.clinerules/ml-training-guidelines.md`.

---

### H3. Low Spearman ρ Values (0.11–0.32)
**Location:** Documented in `docs/analysis_input_output_and_spearman.md`  
**Problem:** Model prediction quality is poor — Spearman correlations between predicted and actual clinical scores are very low.  
**Impact:** The system may not provide clinically meaningful score predictions.  
**Root Causes:** Likely caused by C3 (feature divergence), small dataset (~67 subjects), and possibly inadequate model architecture.  
**Fix:** Requires architectural changes (attention mechanisms, multi-task learning) and pipeline unification.

---

### H4. WebSocket Simplification — Feedback Engine Partially Orphaned
**Location:** `backend/feedback_engine.py`, `backend/main.py`  
**Problem:** The real-time feedback WebSocket was removed (only `clinical_score` WebSocket remains), but `feedback_engine.py` still exists with rule-based feedback logic. The feedback engine is referenced in `main.py` but its integration path is unclear.  
**Impact:** Feedback features may not be fully functional. Users may not receive real-time corrective guidance.  
**Fix:** Either fully integrate feedback engine into the simplified WebSocket flow, or document that it's intentionally deprecated.

---

### H5. Scaler File Compatibility Risk
**Location:** `backend/ml_wrapper.py`, `backend/diagnostic_check.py`  
**Problem:** Scalers fitted during data preparation (`03_extract_joint_features.py`) must match the exact feature set used at inference time. No runtime validation exists to verify `scaler.n_features_in_` matches the feature extractor output dimension.  
**Impact:** If features are added/removed/reordered, the scaler will silently produce wrong values, leading to garbage predictions.  
**Fix:** Add runtime assertion in `ml_wrapper.py` to check `scaler.n_features_in_` against actual feature count before `transform()`.

---

### H6. `evaluate_models.py` Uses Different Pipeline Than Training
**Location:** `training_models/evaluate_models.py`  
**Problem:** This evaluation script uses a completely different feature extraction approach than the training script, making its results non-representative of actual model performance.  
**Impact:** Evaluation metrics reported by this script may not reflect real-world inference performance.  
**Fix:** Unify evaluation to use the same pipeline as training and inference.

## 🟡 MEDIUM Issues

### M1. Hardcoded Database Path
**Location:** `backend/database.py`  
**Problem:** Database path uses environment-dependent logic but fallback is a local directory. No `DATABASE_URL` environment variable support.  
**Fix:** Add `os.getenv("DATABASE_URL", ...)` for flexible deployment.

---

### M2. No Input Validation on WebSocket Frame Data
**Location:** `backend/main.py` (WebSocket handler)  
**Problem:** Frame data received via WebSocket is not validated for shape, type, or value range before being passed to the ML pipeline.  
**Impact:** Malformed input could crash the inference pipeline.  
**Fix:** Add shape/type validation and graceful error responses.

---

### M3. `motion_detector.py` — Motion Thresholds May Be Wrong
**Location:** `backend/motion_detector.py`, `data-preparation/analyze_motion_thresholds.py`  
**Problem:** Motion detection thresholds are hardcoded. The `analyze_motion_thresholds.py` script exists to tune them, but there's no evidence the tuned values were propagated back to the backend.  
**Fix:** Document threshold derivation process, or load thresholds from a config file.

---

### M4. Frontend Dual Styling System (MUI + Tailwind)
**Location:** `frontend/package.json`, various component files  
**Problem:** Both Material-UI and Tailwind CSS are used for styling. This creates bundle bloat and potential style conflicts.  
**Impact:** Larger bundle size, inconsistent styling approach.  
**Fix:** Standardize on one styling system.

---

### M5. Frontend Missing Error Boundaries
**Location:** `frontend/src/`  
**Problem:** No React Error Boundaries found. If the ML inference or WebSocket connection fails, the entire app may crash with an unhandled error.  
**Fix:** Add ErrorBoundary component wrapping key sections.

---

### M6. `data_wrapper.py` Seeds Data on Every Startup
**Location:** `backend/data_wrapper.py`  
**Problem:** Exercise data is seeded on every server startup without checking if it already exists (or with minimal idempotency).  
**Impact:** Potential duplicate data or unnecessary database writes on restart.  
**Fix:** Add proper upsert logic or check for existing records.

---

### M7. No CORS Configuration for Production
**Location:** `backend/main.py`  
**Problem:** CORS is configured with `allow_origins=["*"]` — fine for development but a security risk in production.  
**Fix:** Make CORS origins configurable via environment variable.
